# 匿名测试病例与处方匹配测试策略

## 1. 数据原则

- 默认全部人工编写虚构病例；姓名使用明显虚构标识，日期、机构和编号不映射真实个人。
- 不复制真实病历叙述后“改名”；自由文本最小化。
- 每个病例带 `synthetic: true`、作者、版本、临床审核状态和预期结果。
- CI 增加敏感信息扫描策略（证件号、手机号、邮箱、影像扩展名和数据库文件）；命中即失败并人工复核。

## 2. 病例结构

每个病例包括：人口学最小字段、医疗稳定性、逐项安全筛查、功能评估答案、照护资源、预期 F 等级、主/次模块、目标模式、允许/排除处方、预期辅助等级、阻断/转诊结果和解释理由代码。

## 3. 测试矩阵

每个规则至少包含：

- 典型正例和条件不满足反例。
- 阈值上下边界、缺失值、未知值和过期评估。
- 紧急红旗、模块禁忌、训练禁忌和 AX 阻断。
- F0–F5 与 P/M/R/C/H、A0–A5/AX 的相关组合。
- 人员、器械、空间不足时的替代/人工复核。
- M01/M07/M08 共存、规则冲突、重复训练和总负荷冲突。
- 规则/处方版本升级后的历史回放。
- 未经治疗师确认不得生成护工版导出，以及越权确认失败。

## 4. 测试层次

| 层次 | 验证重点 |
|---|---|
| Schema/契约 | 临床数据完整性、枚举、单位、版本引用 |
| 单元测试 | 单条规则、优先级、理由、缺失值默认阻断 |
| 组合测试 | 多模块合并、冲突、替代、资源限制 |
| 集成测试 | 临时评估到确认、三类角色视图、导出和会话清除 |
| 回归/金标准 | 临床团队批准病例的稳定预期结果 |
| 安全/隐私 | 权限、数据库/日志无患者输入、导出、本地部署、会话超时 |

## 5. 初始病例集建议

每个首版模块首批至少 8 类病例：典型适用、轻/重边界、目标为维持、目标为代偿/舒适、资源不足、训练特异禁忌、红旗阻断、合并模块冲突。具体数量和临床预期由临床负责人批准，不能把测试预期反过来当作临床证据。

## 6. 验收规则

- 安全阻断和越权测试必须 100% 通过，不允许以总体准确率抵消。
- 非安全匹配差异逐例由临床负责人裁决并版本化，不静默修改预期。
- 规则变更若没有关联测试、变更说明和审批状态，则不能发布。
