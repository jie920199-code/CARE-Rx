# 项目章程

## 1. 项目定位

CARE-Rx 是供养老机构康复治疗师使用的功能康复临床决策支持系统。它以安全状态、F0–F5 功能等级、核心功能问题、康复潜力、目标模式和照护条件为输入，用确定性规则从经审批的标准处方库中匹配候选方案。治疗师始终拥有审核、修改、拒绝和签发权。

护工只能使用治疗师确认后导出的简化执行版；老人及家属可使用经确认的宣教版。首版不提供护工在线执行记录。任何角色均不得将系统输出解释为疾病诊断或医疗指令的替代品。

## 2. 首版范围

### 包含

- 老人基本资料（数据最小化）、安全与红旗筛查、综合功能评估。
- F0–F5 分级及理由、M01/M07/M08 核心问题识别。
- P/M/R/C/H 目标模式和 A0–A5/AX 辅助等级。
- 确定性规则匹配、治疗师审核确认、三种内容视图。
- 治疗师确认候选处方，并导出带版本信息的专业版、护工版和宣教版。
- 规则、处方和审核的版本化与审计追踪。

### 不包含

- 自动诊断、自动签发、自由生成临床处方或剂量。
- OpenAI API 或任何云端 AI 患者数据处理。
- 医嘱、药物、急救、收费、医保、电子病历全量替代。
- 首版机构间共享、云托管或公网远程访问。
- 首版系统内患者档案、每日执行记录、纵向复评和患者历史查询；这些能力与“不留存患者数据”冲突，推迟到持久化扩展阶段。

## 3. 用户与权限边界

| 角色 | 主要权限 | 禁止事项 |
|---|---|---|
| 治疗师 | 登录、临时评估、匹配、编辑、确认和导出 | 绕过安全门；无理由覆盖警告 |
| 护工 | 使用治疗师导出的简化执行版 | 登录治疗师工作区、修改或确认处方 |
| 管理员 | 用户、权限、备份、版本部署 | 默认拥有临床签发权 |
| 临床内容管理员 | 维护候选规则/处方版本 | 未审批直接发布 |

首版由使用系统的治疗师承担确认责任；机构仍可规定特定情形必须转医生或康复医师，系统不得覆盖该制度。

## 4. 成功指标（采用的试点建议）

- 100% 导出处方具备治疗师确认人、规则版本、处方库版本和时间戳。
- 所有红旗阳性测试均阻断常规自动匹配。
- 护工版只可在治疗师确认后生成。
- 关键匹配规则对金标准虚构病例达到临床团队批准的一致率。
- 当前会话结束后患者输入自动清除，服务端不得保留可重建患者评估的日志。

## 5. 治理

- 产品负责人确定范围；临床负责人批准临床框架、阈值、处方内容和金标准病例。
- 技术负责人维护 Schema、规则运行时、迁移和测试。
- 规则或处方从 `draft` 经临床复核进入 `approved`，发布为不可变版本；`retired` 版本仅供历史回放。
- 法规适用性、医疗器械软件属性和机构数据治理要求须在试点前由合格人员评估。
