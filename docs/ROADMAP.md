# 分阶段路线图

## 阶段 0：章程与临床治理（当前）

**目标**：锁定边界、安全原则、数据模型和决策点。  
**交付物**：本目录文档、项目骨架、待确认问题、测试策略。  
**验收**：产品和临床负责人逐项批准或提出修改；所有未定临床内容标记待审核；未包含真实患者数据和业务实现。

## 阶段 1：可执行规范与内容样例

**目标**：把 M01/M07/M08 的评估、红旗、处方和规则转换为可校验版本。  
**交付物**：JSON Schema、枚举表、审批工作流、每模块少量临床批准的处方样例、虚构金标准病例、规则解释格式。  
**验收**：Schema 全部通过；每条规则关联正例、反例、边界和安全阻断测试；临床负责人签署首批内容。

## 阶段 2：技术骨架与垂直原型

**目标**：建立 Next.js/TypeScript/Prisma/SQLite 最小骨架，跑通一个无留存的虚构 M01 病例。  
**交付物**：局域网服务、网页登录、短期患者会话、安全筛查、规则匹配、治疗师确认、三类导出、非患者审计。  
**验收**：红旗稳定阻断；未确认不能导出；会话超时后患者输入不可恢复；日志和数据库无患者输入；多终端与基本可访问性检查通过。

## 阶段 3：首版三模块 MVP

**目标**：完成 M01/M07/M08 的无留存评估、三类视图和安全导出。  
**交付物**：完整无留存工作流、治疗师专业版、护工简化版、家属宣教版和导出安全提示。  
**验收**：全部金标准病例通过；治疗师确认率 100%；角色权限、会话清除、导出版本标记和局域网安全测试通过。

## 阶段 4：临床验证与机构试点

**目标**：在批准的治理和隐私方案下验证可用性、匹配一致性与安全性。  
**交付物**：验证方案、培训材料、停机流程、缺陷与安全事件台账、版本冻结候选。  
**验收**：达到预先批准的一致率/可用性阈值；无未关闭高风险问题；法规和数据治理审核完成。

## 阶段 5：患者记录与复评扩展（需另行批准）

**目标**：仅在机构批准留存和合规方案后，增加执行记录、2–4 周复评和历史审计。  
**交付物**：PostgreSQL 方案、患者身份与权限模型、留存/删除/导出政策、加密备份、执行与复评闭环。  
**验收**：隐私影响评估、法规审查、权限测试、备份恢复、审计完整性和临床复评测试全部通过；不得通过共享 SQLite 文件实现。

## 下一阶段可直接执行的任务

1. 由治疗师审核本文采用的临床边界和所有“待临床审核”条目。
2. 建立安全筛查项、评估项、处方、规则和临时会话的 JSON Schema。
3. 定义机构可配置的红旗联系人模板，但不预填临床处置内容。
4. 每个首版模块编写虚构金标准病例和预期结果。
5. 设计无患者留存验证：数据库、日志、崩溃报告和备份均不得出现输入内容。
6. 上述规范获批后再初始化最小 Next.js 工程和测试工具链。
