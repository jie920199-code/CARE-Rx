# 阶段1：可执行规范说明

## 当前交付

- 9 个 JSON Schema：临时评估、标准处方、确定性规则、临时会话、机构安全配置、虚构测试病例、临床审核记录、认证配置和安全导出包。
- 1 份安全筛查定义草案，所有条目均标记“待临床审核”。
- 2 条全局安全规则草案：必需安全信息缺失则停止匹配；新发变化则阻断全部匹配。
- M01、M07、M08 各 1 份不可执行处方模板，只提供字段结构，不提供训练项目或剂量。
- 4 个虚构病例：M01 人工复核、M01 未评估边界、M07 未知安全信息、M08 安全阻断。
- F0～F5 证据域框架和临床内容审核清单；所有操作阈值仍为空并待临床审核。
- 登录与会话安全配置样例、导出契约、局域网威胁模型和部署检查清单。
- 4 个系统安全用例：会话超时清除、未确认禁止导出、未批准内容禁止导出、日志拒绝患者载荷。
- 无第三方依赖的 PowerShell 校验脚本。

## 使用方式

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\validate-clinical-data.ps1
```

当前脚本验证 JSON 可解析性、Schema 元数据、病例虚构标记、安全结果一致性、规则到测试的引用、审批状态和常见敏感信息模式。它不是完整 JSON Schema 运行时；下一技术阶段引入已审核的小型 Schema 校验库后，应运行 Draft 2020-12 完整校验。

## 临床审核清单

1. 逐项批准、修改或删除安全筛查条目，并指定紧急/转诊级别。
2. 给出 F0–F5 的操作性证据要求和矛盾处理规则。
3. 为 M01/M07/M08 各模板填写适应范围、训练内容、剂量、辅助等级、禁忌证、终止和进退阶标准。
4. 为每条临床内容补充可核查证据来源。
5. 为每条规则补充正例、反例、边界例和安全阻断例。
6. 完成机构红旗联系人及离线兜底配置。

在以上项目获批前，所有处方模板均保持 `draft + pending_clinical_review + AX`，不得导出为护工执行版。
