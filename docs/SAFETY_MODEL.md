# 安全模型

## 1. 原则

- 安全门是独立于模块匹配的强制前置层，默认失败关闭（fail closed）。
- 缺失关键安全数据、过期评估或规则错误时，不产生可签发的自动建议。
- “未发现红旗”不等于“适合训练”；仍需训练特异禁忌与治疗师审核。
- 系统提示应区分紧急处置、暂停并转诊、需补充信息、训练调整和普通注意事项。

## 2. 状态机

```text
draft_assessment
  -> safety_blocked | needs_information | eligible_for_matching
eligible_for_matching
  -> recommendation_draft
recommendation_draft
  -> therapist_rejected | therapist_confirmed
therapist_confirmed
  -> exported | session_cleared
```

导出前出现新红旗或关键状态变化时，确认状态失效并重新进入安全筛查。纵向 `active/paused/referred` 状态属于未来持久化扩展。

## 3. 安全事件与终止

每条训练必须引用结构化终止标准。首版护工使用导出的简化版，异常时按导出文件中的机构批准路径停止相关训练并联系治疗师。系统不提供实时异常上报或自动通知，因为无患者数据留存；该能力留待持久化扩展。

## 4. 规则优先级与冲突处理

1. 紧急红旗：阻断全部常规训练建议并显示机构处置路径。
2. 模块级暂停/转诊：阻断相关模块。
3. 训练级绝对禁忌或 AX：排除训练。
4. 相对禁忌/资源限制：降级、替代或人工复核。
5. 适应证匹配和排序。

无法解释的规则冲突、循环依赖、未知枚举或版本缺失均返回安全错误，不猜测结果。

## 5. 审计要求

无留存首版在当前会话中形成评估快照、候选与排除项、匹配/阻断理由、修改差异和确认信息，并把规则版本、处方库版本、治疗师确认人及时间写入导出文件。服务端仅留存账号登录、内容发布和配置变更等非患者审计，不得记录患者输入或导出内容。患者级长期审计需在未来批准数据留存后实现。

## 6. 隐私与本地安全

- 首版 SQLite 数据库仅保存账号、权限、机构配置和临床内容版本，不保存患者输入，并且不得进入 Git。
- 患者输入保存在短期内存会话中，退出、超时、重启或导出后清除；不进入日志、备份或遥测。
- 日志不得包含患者身份、评估答案、匹配结果或自由文本；导出默认不含直接身份字段。
- 本地网页不等于天然安全：需定义监听地址、TLS/局域网开放策略、会话超时、密码和备份加密。

## 7. 上线前安全门槛

- 临床负责人批准红旗、禁忌、终止标准、处置文案和所有首版处方。
- 所有安全阻断金标准测试通过，角色越权测试通过，历史版本可回放。
- 完成威胁建模、备份恢复演练、试点停机/纸质兜底流程和法规评估。
